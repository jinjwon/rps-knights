# 가위바위보 기사 대전 — 게임 콘셉트와 개발 가이드

작성일: 2026-09-08 · 버전: 0.1 · 상태: 기획 검토용

이 문서는 게임을 구현하거나 개발 도구를 설치한 결과가 아니다. 사용자가 정한 방향을 정리하고, 실제 제작을 논의할 수 있도록 상세 규칙과 환경 구축 절차를 제안한다. 수치의 재미·공정성은 아직 플레이로 검증하지 않았다.

## 1. 결정된 방향과 문서의 가정

### 사용자가 제시한 방향

- 카메라·음성 인식 없이 화면의 `가위바위보!` 버튼으로 라운드를 시작한다.
- 플레이어와 상대의 손은 각각 균등 무작위로 정한다. 플레이어가 손 모양을 직접 선택하지 않는다.
- 두 개의 3D 손 모델이 실제 가위바위보처럼 세 번 흔들리고, 마지막 박자에 양쪽 결과를 동시에 공개한다.
- 무작위로 나온 손이 기사 직업을 결정한다. 가위는 검을 든 기사, 바위는 해머 기사, 보는 방패 기사다.
- 가위바위보에서 진 사람에게 짧게 지속되는 패널티를 부여한다.
- 패널티 후보는 이동속도·공격력·방어력·치명타 확률 감소다.
- 가위바위보의 패배가 전투의 패배를 확정하지 않는다. 스킬로 역전할 기회를 둔다.
- 특수 스킬 사용은 최대 3번을 생각하고 있다.
- 총을 든 기사가 있으며, 주먹으로 총을 막을 수 있어야 한다. 해당 막기는 총에만 적용한다.

### 상세화를 위해 제안한 가정

| 항목 | 이 문서의 제안 | 상태 |
|---|---|---|
| 장르 | 짧은 심리전과 조작 전투를 결합한 캐주얼 1대1 액션 대전 | 제안 |
| 시점 | 3D 3인칭, 상대를 중심으로 보는 카메라 | 제안 |
| 최초 실행 환경 | PC, macOS에서 개발·시험 | 제안 |
| 경기 | 라운드 3승 선취 | 제안 |
| 전투 시간 | 라운드당 45초 | 시험값 |
| 스킬 3번 | 각 플레이어가 라운드당 총 3회 사용 | 해석·제안 |
| 주먹의 소유자 | 바위 기사가 해머를 잠시 내려놓고 사용하는 전용 동작 | 해석·제안 |
| 총의 등장 | 가위 카드의 선택 옵션으로 확률적 변형 시도 | 제안 |
| 동시 패널티 수 | 한 번에 한 종류만, 전투 시작 후 4초 | 시험값 |

사용자가 확정한 것처럼 취급하면 안 되는 항목은 위 표에 표시했다. 특히 주먹을 별도 네 번째 직업으로 만들지, 바위의 능력으로 둘지는 추가 결정이 가능하다. 여기서는 기존 세 카드 구성을 유지하는 안으로 작성했다.

## 2. 게임 콘셉트

### 한 문장 소개

손을 흔들며 가위바위보를 한 뒤 그 결과로 전투의 출발 조건을 정하고, 세 번의 특수 스킬과 조작으로 승부를 뒤집는 기사 결투 게임.

### 플레이어가 경험할 감정

1. 선택 전: 상대가 무엇을 낼지 예상한다.
2. 공개 순간: 유리함 또는 짧은 위기를 확인한다.
3. 전투 초반: 패널티를 버티거나 유리한 시간을 활용한다.
4. 전투 중반: 스킬을 지금 쓸지 남길지 결정한다.
5. 결정적 순간: 총알을 주먹으로 막거나, 상대의 빈틈을 공격한다.
6. 결과: 왜 이겼고 졌는지 이해하고 다음 선택을 바꾼다.

### 시각·세계관 방향

무기가 과장된 장난감 같은 판타지 기사 경기장으로 제안한다. 가위 기사는 갈라진 검 실루엣, 바위 기사는 큰 해머와 건틀릿, 보 기사는 넓은 방패, 총 기사는 짧고 굵은 총으로 구별한다. 총알을 주먹으로 막는 것은 이 세계의 과장된 판타지 규칙이다.

카드와 실제 캐릭터에 같은 문양을 사용한다. 색만으로 직업을 구분하지 않는다. 작은 원형 경기장, 낮은 엄폐물, 명확한 바닥 경계를 사용하고 카메라를 가리는 높은 장애물은 첫 시험에서 피한다.

핵심 피드백은 카드 공개음, 패널티 해제음, 스킬 잔여 횟수, 총 발사 예고, 주먹 막기 성공음이다. 온라인 전투에서 화면 연출 때문에 실제 전투 시간을 임의로 멈추지 않는다.

## 3. 경기 진행 규칙

### 전체 흐름

대전 준비 → 시작 버튼 → 양쪽 3D 주먹 흔들기 → 무작위 손 모양 동시 공개 → 총 변형 결과 → 캐릭터 준비 → 전투 → 라운드 결과 → 다음 라운드 또는 경기 종료.

### 무작위 손 결정과 공개 연출

- 매 라운드 `가위바위보!` 버튼 하나로 시작한다. PC에서는 Enter 또는 Space도 사용할 수 있다.
- 시작 순간 플레이어와 상대의 값을 각각 0~2 균등 무작위로 정하고 공개 전까지 숨긴다.
- 양쪽은 3D 주먹 모델로 시작한다. 화면의 “가위… 바위… 보!” 구호에 맞춰 두 손이 세 번 위아래로 흔들린다.
- 마지막 “보!” 박자 뒤 두 3D 손이 정해진 자세로 동시에 변한다.
- 온라인에서는 서버가 양쪽 난수를 만들고 결과를 함께 공개한다. 재접속이나 새로고침으로 유리한 결과를 다시 뽑지 못하게 라운드 결과를 서버에 유지한다.
- 직접 선택이 사라져 가위바위보의 심리전은 약해진다. 대신 짧은 추첨의 기대감과 곧바로 이어지는 전투를 핵심 경험으로 검증한다.

### 가위바위보 판정

행은 내 카드, 열은 상대 카드다. 이 표는 전투 승패가 아니라 패널티 대상만 결정한다.

| 내 카드 / 상대 | 가위 | 바위 | 보 |
|---|---|---|---|
| 가위 | 무승부 | 내 패배 | 내 승리 |
| 바위 | 내 승리 | 무승부 | 내 패배 |
| 보 | 내 패배 | 내 승리 | 무승부 |

무승부면 양측 모두 패널티 없이 전투한다. 승자에게 별도의 공격력 보너스를 추가하지 않는다. 처음부터 직업 상성 추가 피해와 패널티를 동시에 넣으면 불리함이 중복되기 때문이다.

### 전투와 종료

- 양측 체력 100으로 시작하며, 초기 위치·거리는 대칭으로 배치한다.
- 손 모양 공개 후 직업, 총 등장 결과, 패널티를 확인한다. 이 시간에는 이동·공격할 수 없고 패널티 시간도 흐르지 않는다.
- 전투 시작과 함께 45초 제한 시간 및 4초 패널티 시간이 진행된다.
- 상대 체력이 0이 되면 라운드 승리다. 같은 판정 틱에서 둘 다 0이면 무승부다.
- 시간 종료 시 남은 체력 비율이 높은 사람이 승리한다. 같으면 무승부다.
- 라운드 사이 체력·탄약·스킬 횟수·재사용 시간·패널티를 모두 초기화한다.
- 3승을 먼저 달성하면 경기 승리다. 무승부는 승수를 올리지 않는다.
- 장기화를 막기 위해 최대 7라운드로 제한한다. 7라운드 종료 시 승수가 많은 쪽이 승리하고 같으면 경기 무승부다.
- 첫 경기장은 낙사 없이 벽으로 경계를 막는다. 낙사 판정은 별도 확장 사항이다.

## 4. 짧은 패널티

### 적용 방법

모든 후보를 한 번에 적용하지 않고 한 라운드에 하나만 적용한다. 경기 시작 시 네 후보를 섞어 순서를 만들고, 카드 선택 전에 이번 패널티를 공개하는 방식을 제안한다. 네 종류를 모두 사용한 뒤 다시 섞되 직전 종류가 바로 반복되지 않도록 한다.

이렇게 하면 사용자는 선택 전에 위험을 알 수 있고, 패널티 추첨과 총 추첨이 한꺼번에 뒤늦게 발생하는 혼란을 줄일 수 있다. 초반 개발에서는 패널티 종류를 개발용 설정으로 고정해 각각 시험한다.

| 패널티 | 시험값 | 정확한 의미 | 주의점 |
|---|---|---|---|
| 이동속도 감소 | 10% 감소, 4초 | 기본 이동속도에 0.9를 곱함 | 회피 거리·스킬 돌진·조작 응답은 감소시키지 않음 |
| 공격력 감소 | 15% 감소, 4초 | 기본 공격·총알·공격 스킬 피해에 0.85를 곱함 | 공격속도와 재사용 시간은 유지 |
| 방어력 감소 | 20에서 10으로, 4초 | 아래 방어 공식을 사용 | 피해 10% 증가와 같은 뜻이 아님 |
| 치명타 확률 감소 | 15%에서 5%로, 4초 | 10%포인트 감소 | 짧은 전투에서 효과가 전혀 드러나지 않을 수 있음 |

공통 시험값은 기본 방어력 20, 치명타 확률 15%, 치명타 배율 1.5다. 피해 계산은 `기본 피해 × 공격력 보정 × 치명타 배율 × 100 / (100 + 방어력) × 가드 보정` 순서로 한다. 내부 체력은 소수점을 유지하고 표시만 반올림한다.

예: 기본 피해 20인 비치명 공격은 방어력 20에 약 16.67, 방어력 10에 약 18.18 피해를 준다. 방어력 감소 패널티는 이 예시에서 약 9.1%의 피해 증가다.

치명타 확률 감소는 후보로 보존하지만, 네 패널티가 동등하다고 가정하지 않는다. 기본 공격 네 번의 기회가 있어도 확률 차이가 눈에 보이지 않을 수 있다. 반복 시험에서 체감과 결과 차이가 약하면 후보에서 제외하거나 다른 수치로 조정할 항목이다.

패널티는 전투 시작에 한 번만 부여한다. 피격으로 연장하지 않고, 중첩시키지 않으며, 4초 후 원래 능력치로 복원한다. 주먹의 총알 막기 성공은 피해 계산보다 우선하므로 방어력 감소 중에도 성공한 총알은 피해 0이다.

## 5. 직업과 기본 조작

| 직업 | 기본 공격 | 전투 성격 | 대표 특수 스킬 제안 |
|---|---|---|---|
| 가위·검 기사 | 짧은 거리의 검 베기 | 빈틈을 노리는 빠른 접근 | 짧게 돌진하며 한 번 베기 |
| 바위·해머 기사 | 느리고 강한 해머 타격 | 준비 동작을 숨기거나 상대의 접근 예측 | 좁은 전방을 내려치는 강타 |
| 보·방패 기사 | 짧은 방패 타격 | 근접 공격 방어 후 반격 | 짧은 근접 반격 자세 |
| 총 기사·가위 변형 | 탄약이 있으면 사격, 없으면 약한 근접 타격 | 제한된 사격 기회를 맞히는 거리전 | 피해 없이 짧게 뒤로 이동 |

첫 시험에서는 공통 체력·방어력·치명타 확률을 유지하고 공격 거리·준비 동작·회복 동작으로 차이를 만든다. 직업별 피해량은 전투 시험에서 조정한다. 무기의 크기만 보고 판정 거리를 추측하게 하지 않도록 실제 궤적과 맞춘다.

| 입력 | 행동 |
|---|---|
| W/A/S/D | 이동 |
| 마우스 이동 | 카메라 조절 |
| 좌클릭 | 기본 공격 |
| 우클릭 | 기본 근접 가드 |
| Space | 회피 |
| Q | 직업 특수 스킬 |
| E | 바위 기사 전용 총알 막기 |
| Esc | 메뉴, 오프라인은 일시정지 |

기본 근접 가드는 정면 120도에서 오는 근접 피해를 검·바위·총 기사 30%, 방패 기사 60% 줄이는 시험안이다. 총알에는 적용하지 않는다. 가드 중에는 공격하거나 다른 능력을 사용할 수 없다.

회피는 0.3초 동안 빠르게 이동하되 무적을 주지 않고 1초의 재사용 시간을 둔다. 모든 직업이 총알 궤도를 벗어날 수는 있지만, 총알 자체를 무효화하는 전용 능력은 바위의 주먹에만 준다. 이동으로 피하는 것과 막아서 없애는 것을 구분한다.

모바일은 후속 단계에서 가상 이동 패드와 공격·회피·스킬 버튼을 제공한다. 카드 선택뿐 아니라 전투 조작도 필요하므로 클릭 한 번만으로 전체 게임이 진행되는 구조는 아니다.

## 6. 특수 스킬의 세 번 제한

- 각 라운드 시작 시 플레이어마다 공용 특수 스킬 충전 3개를 받는다.
- 첫 버전에서는 직업당 대표 특수 스킬 하나를 세 번 사용하는 방식으로 한다.
- 스킬은 발동한 순간 1개를 소비한다. 빗나가거나 상대가 막아도 돌려주지 않는다.
- 발동 불가능한 상황에서 버튼만 누른 것은 차감하지 않는다.
- 공통 재사용 대기시간은 5초다. 연타로 세 개가 동시에 소비되지 않는다.
- 일반 공격·가드·회피·주먹의 총알 막기는 공용 충전을 소비하지 않는다.
- 주먹 막기는 별도 재사용 시간을 가진 직업 고유 방어 동작으로 정의한다. 이 분류는 총을 막다가 바위의 세 번짜리 공격 기회까지 소진되는 문제를 피하기 위한 제안이다.
- 총 변형 시도의 자원 비용은 아래 규칙에 따라 충전 1개를 먼저 소비한다.

## 7. 총의 등장과 주먹 전용 대응

### 7.1 세 카드 안에서 총을 등장시키는 안

총을 네 번째 손 모양으로 추가하지 않는다. 무작위 결과가 가위일 때 총 변형 확률을 자동으로 한 번 추첨한다.

- 성공 확률 시험값은 20%이며 카드 화면에 표시한다.
- 추첨은 라운드당 한 번이며 플레이어가 별도 옵션을 선택하지 않는다.
- 성공하면 총 기사, 실패하면 검 기사다. 자동 추첨이므로 특수 스킬 충전 차감은 하지 않는 방향으로 변경한다.
- 손 판정의 상성은 성공 여부와 관계없이 가위다. 총 변형 추첨 때문에 이미 정해진 패널티 대상을 다시 바꾸지 않는다.
- 양측이 가위를 내고 한 명만 총으로 변해도 카드 판정은 무승부다.
- 온라인에서는 서버가 변형을 추첨한다. 재접속으로 다시 추첨하지 않는다.

이 비용·확률이 적정하다는 근거는 아직 없다. 총이 너무 약하면 아무도 시도하지 않고, 너무 강하면 가위 선택에 쏠릴 수 있다. 개발 중에는 총을 강제로 등장시키는 시험 설정으로 먼저 대응 가능성을 검사한다.

### 7.2 총의 시험 규칙

| 항목 | 제안 |
|---|---|
| 탄약 | 라운드당 3발, 재장전 없음 |
| 한 발 기본 피해 | 24, 일반 방어·공격력·치명타 보정 적용 |
| 발사 예고 | 0.45초 동안 총구 빛과 소리 표시 |
| 발사 간격 | 발사 후 다음 발사 준비까지 최소 1.5초 |
| 총알 형태 | 눈에 보이고 이동 시간이 있는 투사체 |
| 이동 속도·사거리 | 12m/s, 최대 12m 시험값 |
| 조준 | 예고 시작 시 방향 확정, 그동안 자동 추적 없음 |
| 예고 중 행동 | 이동속도 50%, 가드·회피·스킬로 취소 불가 |
| 탄약 소비 | 실제 발사 시 1발 소비, 체력 0으로 발사 취소되면 미소비 |
| 탄약 소진 후 | 총몸 근접 타격, 기본 피해 10 시험값 |
| 자동 승리 | 없음 |

현실적인 초고속 탄환 대신 예고와 이동 시간이 있는 투사체로 제안한다. 그래야 주먹으로 막는 행동이 운이 아닌 관찰과 타이밍에 연결된다. 발사 직전까지 유도 조준을 허용하면 피하기 어려워지므로 첫 버전에서는 제외한다.

### 7.3 주먹: 총알만 막는 바위의 고유 행동

바위 기사는 E를 누르면 해머를 잠시 내려놓고 건틀릿을 앞으로 내민다.

- 활성 시간 0.45초, 재사용 대기시간 2초, 실패 후 회복 동작 0.25초를 시험한다. 재사용 시간은 동작 시작부터 계산한다.
- 정면 120도 안에서 들어오는 적 총알에만 적용한다.
- 활성 시간 안에 접촉한 첫 총알 하나를 소멸시키고 피해를 0으로 만든다. 성공하면 활성 상태는 즉시 종료하고 0.25초 회복 동작에 들어간다.
- 반사 피해, 자동 돌진, 상대 기절, 체력 회복은 주지 않는다.
- 측면·후면 총알, 검·해머·방패 타격, 총몸 근접 타격, 근접 스킬에는 효과가 없다.
- 막는 동안 다른 공격·가드·회피·특수 스킬을 사용할 수 없다. 이동은 가능하다.
- 충전 세 개와 별도로 작동하며 패널티를 해제하지 않는다.
- 방패의 일반 가드와 반격 스킬도 총알을 무효화하지 못한다. 총에는 회피·엄폐·접근으로 대응한다.
- 경기장 벽과 엄폐물은 총알을 차단한다. “주먹만 총을 막는다”는 캐릭터 능력의 독점이며, 총알이 모든 지형을 통과한다는 뜻은 아니다.

개발 판정은 `공격 종류가 적 총알인가 → 주먹 활성 상태인가 → 정면 범위인가 → 아직 한 발도 막지 않았는가` 순으로 확인한다. 조건이 하나라도 틀리면 정상 피격을 처리한다.

### 7.4 남는 균형 문제

바위는 원래 가위를 이기므로 총 기사에게 카드 단계부터 유리하다. 여기에 총알 막기까지 있어 이중으로 유리해진다. 사용자가 원하는 대응 관계는 유지하되, 자동·상시 면역 대신 타이밍 동작으로 제한한 이유다.

반대로 방패는 가위에게 카드 단계에서 지고 총도 가드할 수 없다. 총 대 방패 조합을 우선 시험해야 한다. 문제가 있으면 총 피해·탄약·예고 시간 또는 해당 조합의 패널티부터 조정하며, 주먹의 총 전용 규칙을 임의로 없애지 않는다.

### 7.5 한 라운드 예시

A는 가위와 총 변형 시도, B는 바위를 확정한다. 이번 패널티는 공격력 감소다. 카드 판정에서 A가 패배한다. A는 추첨에 성공해 총 기사가 되며 스킬 충전이 2개 남는다. 전투 시작 후 A에게 4초간 공격력 감소가 적용된다.

A가 발사 예고를 보이고 B가 E를 적절히 사용하면 첫 탄환은 피해 없이 사라진다. B가 너무 일찍 사용했다면 활성 시간이 끝난 뒤 맞을 수 있다. B가 다른 근접 공격을 같은 동작으로 막으려 하면 정상 피해를 받는다. 탄환을 막았다고 B의 전투 승리가 확정되지는 않는다.

2. Unity 6 LTS 계열 Apple Silicon Editor를 설치한다. 프로젝트가 기록한 기준 버전은 `6000.0.65f1`이다.
3. 설치 옵션에서 Web Build Support를 추가한다.
4. Hub에서 `/Users/gimjin-won/Desktop/GAMEㅎㅎ/game/unity` 폴더를 기존 프로젝트로 추가해 연다.

시험판·베타는 첫 프로젝트의 기본으로 사용하지 않는다. Unity 계정 로그인과 Personal 라이선스 활성화는 사용자가 직접 처리한다.

2. 가위·바위·보 버튼 또는 숫자 1·2·3으로 손을 선택한다.

4. Game 창의 가로세로 크기를 바꿔도 버튼과 손이 잘리지 않는지 확인한다.
5. 이후 3D 전투 장면, 이동·공격·가드·회피·스킬·총알 막기 입력을 추가한다.

### 10.3 Git 준비

[Git 공식 macOS 안내](https://git-scm.com/downloads/mac)를 따라 설치한다. `git --version`으로 기존 설치 여부를 먼저 확인한다. 개발 도구 설치 안내가 뜨면 안내를 완료한 뒤 다시 확인한다.

현재 개인 저장소 `jinjwon/rps-knights`를 계속 사용한다. `.gitignore`는 Unity의 `Library`, `Temp`, `Logs`, `Builds` 등 재생성 파일을 제외한다. `Assets`, `Packages`, `ProjectSettings`와 `.meta` 파일은 버전 관리한다.

### 10.4 Codex에서 같은 프로젝트 사용

1. Codex에서 `/Users/gimjin-won/Desktop/GAMEㅎㅎ/game`을 프로젝트로 열고 Unity 작업은 그 안의 `unity/`로 제한한다.
2. 이 기획 문서를 기준으로 한 번에 한 기능씩 요청한다. 예: 카드 판정, 라운드 전환, 패널티 타이머, 총알 막기 순서다.
3. 각 작업에서 변경한 규칙, 실제 실행 결과, 남은 문제를 함께 확인한다.
4. 엔진 화면에서 플레이해 보는 검증과 화면 없이 하는 규칙 검사를 구분한다.

Hub로 Unity를 설치한 뒤 Editor 버전 확인 예시는 다음과 같다. 실제 설치 버전에 맞게 경로를 바꾼다.

```sh

```

화면 없이 테스트하는 예시는 다음과 같다.

```sh

```

테스트 통과만으로 손 흔들기 속도와 읽기 쉬움이 검증되는 것은 아니므로 브라우저 플레이 확인을 함께 한다.

### 10.5 소재 준비

1. 처음에는 도형으로 이동·공격·승패를 검증한다.
2. 이후 Blender 안정 버전을 설치하고 기사 하나와 무기 변형부터 만든다.
3. 모델은 FBX 또는 glTF/GLB를 교환 형식으로 검토한다. 크기·앞 방향·애니메이션·충돌 범위를 Unity에서 다시 확인한다.
4. 받은 소재의 출처와 라이선스를 `assets/LICENSES.md`에 기록한다.

### 10.6 웹 빌드 만들기

1. Unity 메뉴에서 `RPS Knights > 웹 빌드 만들기`를 누른다.
2. 결과는 `unity/Builds/Web`에 생성한다.
3. 로컬 HTTP 서버로 빌드를 열어 Chrome과 Safari에서 손 선택·애니메이션·동시 공개를 확인한다.
4. 모바일은 iOS Safari 15 이상과 Android Chrome을 대상으로 실제 기기에서 별도 확인한다.
5. 초기 배포는 GitHub Pages 또는 itch.io를 비교하며, 공개 주소를 만들기 전 로딩 크기와 압축 설정을 점검한다.

Unity 웹은 WebGL 2, HTML5, 64비트, WebAssembly 지원 브라우저를 기준으로 한다. 개발 도구가 무료여도 공개 서버 운영·추가 유료 소재까지 무료라는 뜻은 아니다.

| BulletBlock | 바위 주먹의 총알 전용 판정 |
| HUD | 체력·탄약·패널티·횟수 표시 |
| BalanceData | 시간·피해·확률 등 시험 수치 |
| BotController | 비공개 선택을 읽지 않는 카드 선택과 전투 행동 |

핵심 기술은 상태 관리, 3D 이동·충돌, 애니메이션과 피해 판정의 시간 일치, UI, 난수·타이머, 데이터 기반 수치 조정이다. 이를 먼저 익히고 온라인 동기화를 후속으로 다룬다.

친구 대전은 다음 단계에서 서버가 손 확정·확률·피해·승패를 검증하도록 설계한다. Unity의 통신 패키지를 쓰더라도 친구 방 입장, 권한 있는 서버 판정, 연결 끊김, 지연 처리는 별도로 구현해야 한다.

온라인 후속 기본안은 연결 끊김 시 최대 10초 동안 서버에서 양측 전투 시간을 함께 멈추고 재연결을 기다리는 방식이다. 재연결 시 기존 카드·추첨·체력·탄약을 유지하며, 복구 실패 시 이탈자 기권 처리한다. 이를 악용한 반복 중단을 막는 정책과 실제 네트워크 검증은 온라인 단계에서 추가 설계한다.

## 12. 개발 순서와 완료 판단

| 단계 | 만들 것 | 완료 판단 |
|---|---|---|
| 1. 무작위 손 공개 | 단일 시작 버튼, 양쪽 난수, 3D 손 흔들기, 동시 공개 | 아홉 조합이 정확하고 실제 가위바위보 리듬이 느껴짐 |
| 2. 전투 기본 | 경기장, 두 캐릭터, 이동·공격·가드·체력 | 한 라운드가 처음부터 끝까지 진행됨 |
| 3. 패널티·스킬 | 네 후보 개별 시험, 4초 해제, 3회 충전 | 복원·횟수·재사용 시간 오류 없음 |
| 4. 총·주먹 | 총 강제 시험, 총알 전용 막기, 변형 추첨 | 총·근접 판정 구분과 대응 가능성 확인 |
| 5. 봇·연출 | 간단한 상대, 카드·피격·막기 안내 | 설명 없이도 주요 규칙을 알아봄 |
| 6. 친구 대전 | 서버 검증, 초대 입장, 재연결 | 두 기기에서 같은 결과를 봄 |
| 7. 확장 판단 | 랜덤 매칭, 모바일, 추가 맵 | 기본 전투 평가 후 필요성과 비용 판단 |

초기 제외 항목은 카메라·음성, 1인칭 전환, 랭킹, 상점, 계정 성장, GPT NPC다. 총과 주먹은 현재 기획의 중요한 검증 대상이므로 첫 완성 시험판에는 포함한다.

## 13. 검증 항목과 남은 결정

### 반드시 확인할 규칙

- 아홉 카드 조합, 무선택 시간 초과, 확정 후 변경 금지.
- 총 변형 성공·실패 모두 충전 1개만 차감, 실패 재추첨 불가.
- 총 변형이 가위 상성과 이미 정해진 패널티 대상을 바꾸지 않음.
- 패널티 시간이 공개 연출이 아닌 전투 시작부터 흐름, 종료 시 정확히 복원.
- 치명타 확률은 0~100% 범위를 벗어나지 않음.
- 주먹이 정면 총알 한 발만 무효화하고 근접·후면 공격을 막지 않음.
- 같은 총알이 여러 번 피해를 주거나 막힌 뒤 다시 피해를 주지 않음.
- 방패는 근접 공격을 방어하지만 총알은 무효화하지 않음.
- 탄약·스킬·시간이 음수가 되지 않음, 라운드 초기화 시 이전 효과가 남지 않음.
- 동시 사망·시간 종료 동률·최대 7라운드 종료가 규칙대로 처리됨.

### 재미와 균형을 확인할 관찰

비슷한 실력의 두 사람이 직업과 유불리를 바꿔 반복 플레이한다. 적은 표본에서 나온 승률을 정답으로 삼지 않고, 조합별 결과와 플레이 이유를 함께 기록한다.

| 기록 | 확인할 문제 |
|---|---|
| 카드 패자의 전투 승률·행동 | 역전할 기회가 실제 있었는가 |
| 패널티 종류별 초반 피해·평가 | 이속 감소가 과도하거나 치명타 감소가 무의미한가 |
| 가위·총 시도 선택률 | 모든 선택이 총 시도로 쏠리는가 |
| 총 대 바위·총 대 방패 결과 | 바위 이중 우위와 방패 이중 열세가 과도한가 |
| 주먹 성공률·실패 이유 | 타이밍을 읽을 수 있는가, 방향 안내가 명확한가 |
| 탄약 소진 후 남은 체력·시간 | 총 기사가 계속 도망치기만 하게 되는가 |
| 스킬을 남긴 채 패배한 이유 | 횟수·발동 조건·가치를 이해하지 못했는가 |
| 한 번 더 플레이하려는 이유 | 카드 심리전과 전투 중 무엇이 재도전을 만드는가 |

문서 검토 시 먼저 결정할 것은 네 가지다: 주먹을 바위 고유 동작으로 둘지, 총을 가위의 확률 변형으로 둘지, 스킬 3회를 라운드 단위로 둘지, 패널티 종류를 선택 전에 공개할지. 나머지 수치는 그 결정 후 시험으로 조정한다.
